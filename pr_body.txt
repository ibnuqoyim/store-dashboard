## 📋 Deskripsi PR (Task 10)

### 🔴 As-Is (Kondisi Sebelumnya)
- Target Batch PO pada header POS masih berupa dropdown statis harcoded (`BATCH-20260915-PAGI`) tanpa opsi untuk membuat Batch PO baru secara langsung.
- Input Nama Pembeli masih berupa teks manual tanpa autocomplete ke master data pelanggan (`customers`), sehingga no WhatsApp dan kurir default harus diketik ulang manual.

### 🟢 Expected (Hasil yang Diharapkan)
- **Target Batch PO Terhubung dengan Pre-Orders (`batch_po`)**:
  - Dropdown batch membaca daftar `BatchPO` secara dinamis.
  - Pengguna dapat memilih salah satu Batch PO aktif atau memilih `+ Buat Batch PO Baru...` (atau klik tombol ikon `CalendarPlus`) untuk langsung membuat batch pre-order baru *on-the-fly*.
- **Customer Autocomplete & Auto-Fill**:
  - Field Nama Pembeli dilengkapi *dropdown autocomplete list* yang membaca master data `customers`.
  - Ketika nama pembeli dipilih, No. WhatsApp dan Kurir Default otomatis ter-fill ke form POS.
  - Jika nama pembeli belum terdaftar, sistem otomatis mendaftarkan pelanggan baru saat order disimpan.

- **Update Types & Mock**: `lib/types/batch.ts`, `lib/mock/batch-pos-mock.ts` (Menambahkan `Customer` & `BatchPO` models + mock data).
- **Update Component**: `components/BatchPosHeader.tsx` (Dynamic batch selector + inline Form pembuatan Batch PO baru).
- **Update Component**: `components/CustomerShippingForm.tsx` (Autocomplete input + dropdown saran pembeli + auto-fill kontak & kurir).
- **Update Component**: `components/BatchPosLayoutClient.tsx` (State integration untuk dynamic batch PO & autocomplete customer list).
